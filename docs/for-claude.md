# Claudeでの使い方 / How to Use with Claude

---

## はじめに

このガイドでは、本リポジトリのコンテキストファイルとプロンプトテンプレートを、Claude で利用する方法を説明します。

Claude は長文コンテキストの処理が得意なため、PM業務の文書整理・状況分析に向いています。

> [!IMPORTANT]
> 顧客情報・個人情報・認証情報（APIキー・パスワード等）は、Claude に入力しないでください。
> AI出力は業務判断の代替ではありません。出力内容は必ず人間が確認してください。

---

## 基本手順

### 1. コンテキストファイルの内容を確認する

まず `contexts/PM_CONTEXT.md` を開き、内容を確認します。

### 2. Claude でチャットを開く

Claude（https://claude.ai/）でチャットを開きます。

### 3. コンテキストを貼り付けて依頼する

チャットの最初のメッセージに、コンテキストファイルの内容と案件情報を貼り付けて依頼します。

```text
以下のコンテキストを前提として振る舞ってください。

【コンテキスト】
[PM_CONTEXT.md の内容をここに貼り付ける]

---

それでは、以下を依頼します。

[依頼内容と案件状況（機密情報はマスキング済み）]
```

## Claude Projects での利用

Claude には「Projects」機能があります（提供状況はプランによって異なります）。

Projects を利用すると、プロジェクトに「指示（Instructions）」を設定でき、同じプロジェクト内のチャットでは毎回コンテキストを貼り付ける手間を省けます。

設定の考え方：

1. Claude で新しいプロジェクトを作成する
2. プロジェクトの「Project instructions」に `claude/claude-project-instructions.md` の内容を貼り付ける
3. 以降は案件状況だけを入力すれば、PM 支援の前提で応答してもらえる
4. Projects には関連ファイルをアップロードすることもできる（機密情報が含まれないことを確認してから）

## PM_CONTEXT.md と用途別コンテキストの組み合わせ方

複数のコンテキストを組み合わせる場合は、以下のように構造化して貼り付けると効果的です。

```text
【コンテキスト1：PM業務の基本前提】
[PM_CONTEXT.md の内容]

---

【コンテキスト2：今回の用途別前提】
[PROJECT_HEALTH_CHECK.md / STATUS_REPORT_CONTEXT.md 等の内容]

---

【依頼内容と案件状況】
[案件の状況（機密情報はマスキング済み）]
```

---

## 長文コンテキストを渡す場合の注意

Claude は長文コンテキストを処理できますが、以下の点に注意してください。

- **不要な情報は省く**：議事録全文・詳細ログ・関係ない情報は除外し、必要な情報だけを渡す
- **構造化する**：箇条書き・表形式・見出しを使って情報を整理してから渡す
- **機密情報の確認**：長文ほど機密情報が混入しやすくなります。入力前に必ず確認する
- **コンテキスト長の制限**：モデルによってコンテキスト長に制限があります。情報量が多い場合は分割して依頼する

## サンプルプロンプト

以下のプロンプトは、コピーして使用できます。

機密情報・個人情報が含まれていないことを確認してから使用してください。

---

### サンプルプロンプト 1：会議メモからの状況整理

```text
以下のコンテキストを前提として、会議メモをPM視点で整理してください。
事実・推測・課題・次アクション・顧客確認事項に分類してください。

【PM_CONTEXT.md の内容】
（ここにPM_CONTEXT.mdの内容を貼り付ける）

【会議メモ（個人名・顧客名・機密情報はマスキング済み）】
- 先週の定例で、仕様変更の方針が決定されず持ち越しとなった
- テスト工程の遅れについて、顧客担当者Aから「スケジュールを見直してほしい」との要望があった
- 開発担当者Bから、「外部API連携の仕様が確定しないと着手できない機能が3件ある」と報告があった
- 次回定例は来週火曜日
```

---

### サンプルプロンプト 2：リスクの洗い出しと優先度整理

```text
以下のコンテキストを前提として、案件のリスクを洗い出し、優先度を整理してください。
見落としているリスクがあれば、PMの観点から追加してください。

【ISSUE_RISK_CONTEXT.md の内容】
（ここにISSUE_RISK_CONTEXT.mdの内容を貼り付ける）

【案件状況と既知のリスク（機密情報はマスキング済み）】
- プロジェクト概要：[例：受託開発、フェーズ：開発終盤〜テスト開始]
- 既知のリスク：
  - 外部API仕様の確定が遅れている
  - テスト要員が1名不足
  - 顧客側の受入テスト担当者が未定
- 追加で確認したいこと：これ以外に見落としているリスクはないか
```

---

### サンプルプロンプト 3：上長向け報告サマリーの作成

```text
以下のコンテキストを前提として、上長向けの報告サマリーを作成してください。
端的に現状・課題・相談事項・次アクションをまとめてください。

【STATUS_REPORT_CONTEXT.md の内容】
（ここにSTATUS_REPORT_CONTEXT.mdの内容を貼り付ける）

【今週の状況（機密情報はマスキング済み）】
- 全体進捗：[例：70%、開発はほぼ完了、テスト工程に移行中]
- 課題：[例：テストで不具合多発、修正対応が遅れている]
- リスク：[例：このペースでは納期が厳しくなる可能性がある]
- 相談事項：[例：追加のテスト要員を確保する必要があるかどうか判断してほしい]
```

## 注意事項

- Claudeへの入力は、機密情報・個人情報・認証情報を含まないようにしてください
- AI出力はたたき台です。そのまま顧客提出・社内報告・契約判断に使わないでください
- Claudeのデータ利用設定（学習への利用可否）を事前に確認してください
- 組織でAnthropicの法人向けプランを利用している場合は、組織の設定・ポリシーを確認してください

詳細は [docs/ai-safety.md](ai-safety.md) を参照してください。
